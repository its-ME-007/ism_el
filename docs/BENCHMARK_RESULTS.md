These are pilot/reference results, not final research claims.\n\n## At a glance\n\n| Track | Model | Fit data | Held-out result |\n|---|---|---:|---:|\n| AG News topic classification | TF-IDF + XGBoost | 5,000 of 120,000 train rows | Accuracy **0.793**; macro-F1 **0.795** |\n| AG News topic classification | TF-IDF + Random Forest | 5,000 of 120,000 train rows | Accuracy **0.823**; macro-F1 **0.823** |\n| 20 Newsgroups topic classification | TF-IDF + XGBoost | 5,000 of 9,915 train rows | Accuracy **0.554**; macro-F1 **0.547** |\n| 20 Newsgroups topic classification | TF-IDF + Random Forest | 5,000 of 9,915 train rows | Accuracy **0.576**; macro-F1 **0.557** |\n| Reuters topic classification | TF-IDF + XGBoost, one-vs-rest | 2,998 of 7,733 labeled train rows; 71 modeled topics | Micro-F1 **0.819**; macro-F1 **0.371** |\n| Reuters topic classification | TF-IDF + Random Forest | 2,998 of 7,733 labeled train rows; 71 modeled topics | Micro-F1 **0.744**; macro-F1 **0.148** |\n| AG News clustering | TF-IDF + MiniBatchKMeans, 4 clusters | 5,000 train rows | Test ARI **0.029**; NMI **0.053** |\n| Synthetic storage tier | XGBoost tier classifier | 480 temporal training/validation examples | Test accuracy **1.000**; macro-F1 **1.000** |\n| Synthetic future access | XGBoost regressor, 24-hour target | 480 temporal training/validation examples | Test ROC-AUC **0.763**; Brier score **0.095** |\n\nAG News metrics use its full 7,600-row official test split. 20 Newsgroups metrics use 5,000 sampled training rows, its 1,099-row official validation split, and all 7,317 official test rows. See the JSON metrics for per-class results and exact exclusions.\n\n## Predictions and input features\n\n### News topic classifiers\n\nThe AG News and Reuters classifiers predict **news topics from article text**. Input is the article's cleaned full text, transformed into sparse TF-IDF unigram and bigram vectors. The AG News pilot uses a 5,000-term vocabulary; the Reuters pilot uses 3,000 terms. Vectorizers are fit only on the sampled training records. The classifiers do not use article metadata, access histories, or storage-tier labels.\n\n### Storage-tier and future-access models\n\nBoth storage models use the following **37 input features**. The workload features are computed only from events strictly earlier than the prediction timestamp. Metadata is static or time-relative file metadata. One-hot fields are listed by group; each category value is a separate feature.\n\n**Workload history (10):**\n\n- `access_count_1h`, `access_count_24h`, `access_count_7d`, `access_count_30d`\n- `last_access_hours`, `time_since_creation_hours`\n- `mean_inter_arrival_hours`, `std_inter_arrival_hours`\n- `read_write_ratio`, `periodicity_score`\n\n**Numeric/boolean metadata (6):**\n\n- `size_log_bytes`, `content_chars`, `created_age_days`, `modified_age_days`\n- `indexed`, `compressed`\n\n**One-hot metadata (21):**\n\n- `category=`: Finance, Legal, HR, Engineering, Research, Marketing, Operations, Security, System (9)\n- `file_type=`: document, archive, database, log (4)\n- `department=`: IT, Finance, HR, Operations (4)\n- `confidentiality=`: public, internal, confidential, restricted (4)\n\nThe two prediction targets are:\n\n- **Future access:** binary label `1` when the file has one or more accesses in the next 24 hours, otherwise `0`.\n- **Tier:** HOT for 50 or more accesses in the next 24 hours; WARM for 5–49; COLD for 0–4. These are explicit simulator-derived labels, not observed enterprise decisions.\n\n**Not currently included as tier-model inputs:** TF-IDF features, Sentence Transformer embeddings, RAG outputs, file identifiers, or future events. The benchmark deliberately starts with workload and metadata features so their contribution can be isolated before adding text representations.\n\n## Synthetic storage-tier benchmark details\n\n- Generated **120 synthetic enterprise files** and **145,438 access events** over 30 days, with seed 42.\n- Training snapshots use days 5, 10, and 15 (360 file-time rows); validation uses day 20 (120 rows); final test uses day 26 (120 rows). Each sample's 24-hour label window follows its feature timestamp.\n- Models were refit on train plus validation snapshots before the final test scoring.\n- Tier classifier test accuracy was 1.000 (majority-class baseline: 0.400). Future-access test ROC-AUC was 0.763; the test positive rate was 0.917, so always predicting positive also has 0.917 accuracy. Use AUC and Brier score rather than accuracy alone for this imbalanced access target.\n- The SimPy integration run processed all 145,438 events. A model-driven tier policy made 78 migrations and had 342 ms mean and 1,250 ms p95 access latency, compared with the all-COLD reference at 3,084 ms mean and 23,696 ms p95. Model-driven HOT-tier hit rate was 0.687; the all-COLD reference was 0.\n- **Synthetic limitation:** the same files appear in earlier training snapshots and the later test snapshot, and targets come directly from generated workload patterns. The perfect tier score therefore shows the pipeline can learn this simulator's rules; it does not establish generalization to unseen files, real organizations, or real access traces.\n- The original synthetic report predates the product ablation and its cost separation; use the newer report below for distinct storage and migration cost values.\n\n## Product revamp: matched A/B/C semantic ablation\n\nRun with `python -m src.tiering.experiments.product_ablation`. The result is recorded in `results/metrics/product_ablation_synthetic.json`; the matched models and fitted train-only TF-IDF vectorizer are in `results/models/product_ablation_synthetic.joblib`.\n\n- **A:** metadata + past workload (36 features); **B:** content-only TF-IDF (256 features); **C:** metadata + past workload + TF-IDF (292 features).\n- All three use the same generated files, 24-hour future-access targets, fixed tier mapping, train cutoffs (days 5/10/15), validation cutoff (day 20), and test cutoff (day 26). An 80/20 category-stratified file-identity split is fixed by seed 42. The vocabulary is fit on training identities only.\n- On the unseen-file test subset (24 files), A achieved count MAE **3.93** and tier macro-F1 **1.000**; B achieved count MAE **44.75** and macro-F1 **0.227**; C achieved count MAE **3.64** and macro-F1 **1.000**. On the later-period test over all 120 files, A and C had count MAE **4.80** and **4.72**, respectively, with tier macro-F1 **0.991** for both.\n- For the secondary any-access target on unseen files, A and C both had ROC-AUC **0.932**, average precision **0.994**, and Brier score **0.063**; B had ROC-AUC **0.455**, average precision **0.932**, and Brier score **0.086**. The high average precision must be read alongside the test positive rate in the JSON report because this target is imbalanced.\n- For the post-cutoff SimPy period (18,569 accesses), the all-COLD policy had mean latency **3,137 ms**, p95 **23,696 ms**, and hot-tier hit rate **0.000**. A and C each had mean latency **936 ms**, p95 **3,490 ms**, hot-tier hit rate **0.507**, 78 migrations, storage cost **0.000400** (configured cost units), and migration cost **235,378** (configured cost units). B had mean latency **996 ms**, p95 **3,490 ms**, hit rate **0.422**, 73 migrations, storage cost **0.000403**, and migration cost **238,533**.\n- The simulator now reports storage cost separately from migration cost. Both use configured cost units; calibration and interpretation depend on the experimental tier-cost assumptions.\n- **Interpretation:** the workload generator assigns a persistent access pattern to each file independently of its text. B's perfect known-file tier score (despite poor unseen-file performance) is consistent with the model using static text vectors as file fingerprints to memorize stable per-file demand. It is not evidence that semantic meaning predicts demand. The primary unseen-file comparison shows no measured benefit from adding semantics here: A and C have the same tier macro-F1, and C's small count-MAE difference is not supported by multiple seeds. A real text/access dataset with a proven join is required for a substantive semantic claim.\n- The simulator receives all pre-cutoff events only to warm historical features. It excludes those events, migrations, and storage charges from test metrics, and begins tier decisions at the day-26 test cutoff.\n\n## Clustering and semantic embedding status\n\n- MiniBatchKMeans was fit on train-only AG News TF-IDF features. Test ARI/NMI are close to zero and the clusters are highly imbalanced; these clusters do not recover the four news topics well in this pilot.\n- Sentence Transformer embeddings were **not run**: `sentence-transformers`, PyTorch, and FAISS are not installed in this environment. A pretrained embedding encoder is an optional feature experiment, not a required dependency for the workload/metadata tier models. No embedding model was fine-tuned.\n- RAG was not run. Retrieval and RAG are separate from the supervised predictions above and are not required for the current tier classifier.\n\n## Reproduce the runs\n\nRun from the project root after dataset cleaning:\n\n```powershell\npython -m src.tiering.models.news_training --dataset ag_news --model xgboost --max-train-samples 5000 --max-features 5000\npython -m src.tiering.models.news_training --dataset ag_news --model random_forest --max-train-samples 5000 --max-features 5000\npython -m src.tiering.models.news_training --dataset 20_newsgroups --model xgboost --max-train-samples 5000 --max-features 5000\npython -m src.tiering.models.news_training --dataset 20_newsgroups --model random_forest --max-train-samples 5000 --max-features 5000\npython -m src.tiering.models.news_training --dataset reuters21578 --model xgboost --max-train-samples 3000 --max-features 3000\npython -m src.tiering.models.news_training --dataset reuters21578 --model random_forest --max-train-samples 3000 --max-features 3000\npython -m src.tiering.experiments.news_clustering\npython -m src.tiering.experiments.train_synthetic_tiering_models\npython -m src.tiering.experiments.product_ablation\n```\n\nThe sample selections are deterministic.
